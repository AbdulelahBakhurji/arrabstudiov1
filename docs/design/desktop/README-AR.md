# Arrab Studio — النسخة المحسّنة

نسخة مستقلة مبنية على التصميم المرفق **Arrab-Desktop-Design-Previous (1).zip**، مع الحفاظ على هويته وألوانه. المصدر المعدّل داخل `source`، والمشروع الآخر الموجود في مساحة العمل لم يُستبدل.

## افتح التصميم

افتح **Arrab-Design.html** في متصفحك. يحتوي على التطبيق والألوان والصور داخله؛ لا يحتاج تثبيتًا أو خادمًا للمعاينة. زر «شاشات التصميم · معاينة» يعرض وجهات الأفراد والمنظمات.

هذه معاينة محلية ببيانات تجريبية وردود مصطنعة مكتوب عليها ذلك، دون ذكاء اصطناعي فعلي أو ربط حسابات أو دفع. الرد التجريبي يظهر تدريجيًا لتجربة الكتابة والإيقاف. بيانات المعاينة مؤقتة وتعود إلى البداية عند إعادة تحميل الملف.

الصورة `preview/arrab-improved.png` تصوّر ثابت مرسوم لتوضيح المظهر؛ ليست لقطة تشغيل أو إثباتًا لاختبار التخطيط في المتصفح. SVG وسكربت إنتاجها مرفقان.

## ما تغيّر

- وُحّدت لغة التصميم بين واجهتي «الأفراد» و«المنظمات»: كانت شاشات المنظمات (المحادثة، العمل التعاوني، فريق العمل، مكتب الموظف، الإعدادات، تسجيل الدخول) تستخدم نظام ألوان منفصل وغير مكتمل، وتبقى داكنة حتى في الوضع الفاتح. الآن تتشارك الواجهتان نفس الإطار (الشعار، شريط التنقل، تبديل الدور) ونفس رموز الألوان (الخلفية، الأسطح، الحدود، التمييز البنفسجي)، وتستجيبان بشكل صحيح لتبديل الوضع الفاتح/الداكن.
- تُحفظ مسودة مستقلة لكل رفيق ولكل مساحة طوال جلسة التطبيق، بما يشمل التنقل وإعادة التحميل عند توفر sessionStorage. الانتقال من بطاقة إلى محادثة يضيف سياقها إلى المسودة الموجودة ولا يمسحها.
- يمكن كتابة الرسالة التالية أثناء استقبال الرد. زر «إيقاف» يقطع استقبال الرد ويمنع إعادة إرسال الطلب الملغى تلقائيًا. هذا لا يثبت إيقاف المعالجة أو احتساب الاستخدام لدى الخادم، الذي لا تتضمنه الحزمة.
- استرجاع رسالة فاشلة يضيفها إلى النص الجديد بدل استبداله. القراءة للأعلى أثناء الرد لا تسحب المستخدم إلى أسفل تلقائيًا.
- «إضافة مهمة» تضيف مهمة مباشرة، و«حفظ فكرة» يبقيها في المقترحات. المقترحات الآلية تظل بحاجة لقبول.
- بطاقات اللوحة تفتح المهمة أو الموضوع المحدد مع تمييزه وإظهاره، بما في ذلك المكتمل والمؤرشف. مُنعت مطابقة العناصر بين الشخصي والمهني خطأً.
- قسم «المهام» منفصل بالاسم عن مساحة «المهني»، و«المواضيع» حلّت محل التسمية الملتبسة «الملفات المستمرة».
- تكبير النصوص الصغيرة وتحسين التباين والتركيز بلوحة المفاتيح، مع الحفاظ على الخلفية الرمادية والبنفسجي والأشكال المستديرة.
- صار الاقتراح «لخّص لي هذا النص»؛ هذه الشاشة لا تدّعي دعم رفع الملفات.
- إعداد المحادثة أوضح عند عدم جاهزية الخدمة في التطبيق الحقيقي.

## تجربة سريعة

1. اكتب مسودة دون إرسالها، بدّل إلى «المهني» ثم ارجع إلى «الشخصي»؛ تبقى المسودة.
2. أرسل رسالة في المعاينة، واكتب رسالة ثانية أثناء الرد التجريبي، ثم اضغط «إيقاف»؛ يبقى النص الجديد.
3. افتح «المهام»، أدخل مهمة واضغط «إضافة مهمة»؛ تظهر مباشرة في التزاماتك. «حفظ فكرة» يضعها في المقترحات.
4. افتح بطاقة مهمة أو موضوع من «اللوحة»؛ يظهر عنصرها المحدد.

## المصدر والتحقق

من مجلد `source`، بعد تثبيت Node.js 22+ وpnpm:

```sh
pnpm install
pnpm test
pnpm typecheck
pnpm build
```

لإعادة بناء المعاينة المستقلة من جذر هذه الحزمة:

```sh
node preview-tools/build-preview.mjs
```

لإعادة إنتاج الصورة التوضيحية (تحتاج مكتبة sharp ضمن اعتماديات المصدر وخطًا عربيًا متاحًا):

```sh
node preview-tools/render-overview.mjs
```

الفحوص المنفذة ونتائجها موجودة في `VERIFICATION.md`. لم تُختبر الخدمات الحقيقية أو يُبنَ مُثبّت Tauri أصلي. مُنع فتح ملف HTML المحلي بأداة المتصفح بسبب سياسة أمان الروابط؛ لا ندّعي إجراء اختبار بصري تفاعلي في المتصفح. التحقق الآلي من المكونات مع بيانات بديلة لا يعادل اختبارًا مع مستخدمين.

`manifest.json` يجرد ملفات هذه النسخة وبصماتها. بيانات التحقق القديمة محفوظة باسم `reference/original-*` لتوثيق الأصل فقط، ولا تصف الملفات المعدّلة.
